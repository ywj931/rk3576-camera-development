## 2. 本次修正内容

1. `fps` 命令不再以“RKAIQ 接口返回成功”作为最终成功条件。
2. 程序清空旧统计窗口后，观察 V4L2 帧时间戳；连续三个帧间隔达到目标，且实测误差不超过 5%，才返回 `fps_stable=1`。
3. 解决了从 30 Hz 切到 4/2 Hz 时，旧帧混入统计窗口、短时间误报 20 多 Hz 的问题。
4. 每台相机分别保存请求的曝光、增益、ISO 和帧率，设置一侧不会拿另一侧或上一次查询值覆盖。
5. 手动曝光/增益设置后轮询 RKAIQ 实际值，达到容差才返回成功，并输出 `manual_settings_verified=1`。
6. 保存照片时，把 DQBUF 对应的 `frame_id`、系统时间、触发 ID 和当时查询到的曝光参数一起写入 CSV 和 JPEG EXIF `UserComment`。

## 4. 阶段一：4 Hz / 2 Hz 稳定性

### 4.1 测试命令

```text
stream-start all
wait 2000
fps 0 4
fps 1 2
capture-status all
wait 10000
capture-status all
status all
```

新版 `fps` 命令会等待实测稳定。成功输出示例：

```text
OK command=fps camera_id=0 requested_fps_x1000=4000 measured_fps_x1000=4003 fps_stable=1
OK command=fps camera_id=1 requested_fps_x1000=2000 measured_fps_x1000=2001 fps_stable=1
```

### 4.2 实测结果

| 相机 | AIQ 回读 | V4L2 实测 | 10 秒帧数变化 | 稳定段 sequence_drops |
|---|---:|---:|---:|---:|
| cam0 | 4.000 Hz | 4.003 Hz | 63 → 103，增加 40 | 11 → 11 |
| cam1 | 2.000 Hz | 2.001 Hz | 81 → 101，增加 20 | 14 → 14 |

判定依据：

- `fps_target_x1000` 分别为 4000、2000。
- `fps_stable=1`。
- 10 秒内分别增加 40、20 帧。
- 稳定观察期间 `sequence_drops` 没有继续增加。

启动和降帧率过渡期间出现的 11/14 个序号跳变不计入稳定段；后续计数保持不变。

## 5. 阶段二：双路参数独立及回读

### 5.1 设置两路不同参数

```text
exposure 0 5000
gain 0 2000
exposure 1 20000
iso 1 400
status all
```

实测：

| 相机 | 请求曝光 | 实际曝光 | 请求增益 | 实际增益 | 有效 ISO | 帧率 |
|---|---:|---:|---:|---:|---:|---:|
| cam0 | 5000 us | 5004 us | 2.000x | 2.000x | 100 | 4.000 Hz |
| cam1 | 20000 us | 19996 us | 8.000x | 8.000x | 400 | 2.000 Hz |

两路均为 `manual_settings_verified=1`。

### 5.2 独立性测试

依次只修改一项，每次执行 `status all`：

```text
exposure 0 10000
status all

iso 1 600
status all

gain 0 3000
status all
```

最终实测：

| 操作 | 被修改相机 | 修改后实际值 | 另一相机是否变化 |
|---|---|---|---|
| cam0 曝光改为 10000 us | cam0 | 9998 us、2.000x | cam1 保持 19996 us、8.000x |
| cam1 ISO 改为 600 | cam1 | 19996 us、12.000x、ISO 600 | cam0 保持 9998 us、2.000x |
| cam0 增益改为 3.000x | cam0 | 9998 us、3.000x、ISO 150 | cam1 保持 19996 us、12.000x、ISO 600 |

整个过程中 cam0/cam1 的 V4L2 实测帧率保持 4.003/2.001 Hz，均为 `fps_stable=1`。

### 5.3 为什么同时显示 aiq_iso 和 iso

当前 RKAIQ 6.0 查询结构中的原始 `aiq_iso` 一直返回 0，不能把 0 当成有效 ISO。程序同时输出：

- `aiq_iso=0`：RKAIQ 原字段的真实返回值，保留用于诊断。
- `iso=模拟增益×数字增益×ISP增益×50`：当前有效 ISO。
- `iso_estimated=1`：明确说明 ISO 是按 IMX586 当前增益和基准 ISO 50 换算，不冒充 RKAIQ 原生 ISO。

本次数字增益和 ISP 增益都是 1.000x，所以 ISO 100/150/400/600 分别与 2x/3x/8x/12x 一致。控制验收应同时检查 `gain_x1000` 和 `iso`；如果产品规范强制要求 RKAIQ 原生 ISO 非 0，还需要继续修 RKAIQ/IQ 数据链路。

### 6.4 三方一致性证据

最后一组照片：

```text

```

对 cam0 最后一张照片，三个位置均记录：


3. JPEG EXIF `UserComment` 中的相同字段。

此外，`stage3_final_bind.csv` 同一 trigger ID 下的双路 frame ID 也与照片完全一致。

### 6.5 本阶段边界

本次 `response_offset_ns=0`，所以 `exposure_start_realtime_ns` 是以软件触发时刻为基准的逻辑值，并非示波器测出的 IMX586 实际曝光起点。当前已证明参数是在对应帧 DQBUF 时读取并跟随 frame ID 保存；接入 MCU 后还需要：

1. 用 PPS/UTC 数据令 `utc_valid=1`。
2. 用真实 UART 触发替代 `SIM`。
3. 测量并标定每路 `sensor_response_offset_ns`。
4. 如需两路同时曝光，再单独验收 XVS/FSIN 硬件同步误差。

本次自由运行双路同一触发的帧时间差约 163.373 ms，这不能算硬件同步；它只用于证明配对和记录逻辑没有串帧。
