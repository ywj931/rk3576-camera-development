# RK3576 + IMX586 单路 UVC 4000x3000 实现与验证

## 1. 本阶段目标

- 使用 camera0，暂不同时暴露 camera1。
- 相机采集格式保持 4000x3000 NV12M。
- RK3576 MPP 硬件编码为 4000x3000 MJPEG，质量系数 80。
- 通过 USB UVC 输出，默认 10 fps，同时在描述符中保留 5 fps。
- 保留现有 RNDIS USB 网络，同时增加一个 UVC 接口；系统自带
  `uvc-gadget` 不读取相机，统一由 `camera_aiq_test` 管理采集、AIQ 和 UVC。
- 不加入 UART 和硬件同步；后续增加同步时，UVC 仍消费同步后的 camera0 帧，不需要改变 UVC 协议层。

## 2. 数据链路

```text
IMX586 camera0
    -> ISP/RKAIQ
    -> /dev/video-camera0 (4000x3000 NV12M)
    -> capture_backend
    -> 深度为 1 的最新帧队列
    -> RK3576 MPP MJPEG 硬件编码
    -> Rockchip UVC gadget video node
    -> USB 主机 /dev/videoX (4000x3000 MJPEG)
```

使用 MJPEG 而不是 4000x3000 原始 YUYV，是因为原始数据在 10 fps 下约为
240 MB/s，USB 链路不可接受。MJPEG 能明显降低 USB 带宽，并且 PC 端 UVC
软件普遍支持。

采集线程不等待 JPEG 编码：队列满时丢弃旧帧、保留最新帧。这样 UVC 负载不
会阻塞 V4L2 采集，也不会影响后续 eMMC 保存链路。

## 3. SDK 改动

- `camera_uvc_backend.cpp/.h`：MPP MJPEG 编码、UVC 启停、最新帧队列和统计。
- `capture_backend.cpp/.h`：增加取帧回调，DQBUF 后将 camera0 帧交给 UVC。
- `camera_aiq_test.cpp`：增加 `uvc-start 0`、`uvc-stop`、`uvc-status`。
- `Makefile.camera_aiq`：交叉编译 UVC/MPP 依赖。
- `external/uvc_app/uvc/uvc-gadget.c`：增加 4000x3000 的 10/5 fps 协商项。
- `external/rkscript/usbdevice`：增加 4000x3000 描述符、外部程序接管 UVC
  节点以及 4000x3000-only 开关。
- `zz-camera-uvc-4000x3000.sh`：板端持久 USB gadget 配置。文件名以 `zz-`
  开头，确保它在 `rndis.sh` 后加载，最终功能集合为 `rndis uvc`。

## 5. 板端部署和配置

部署前必须备份，不覆盖 IQ 目录：

```bash
STAMP=$(date +%Y%m%d_%H%M%S)
mkdir -p /root/camera_uvc_backup_$STAMP
cp -a /usr/bin/usbdevice /root/camera_uvc_backup_$STAMP/
cp -a /etc/profile.d/usbdevice.sh /root/camera_uvc_backup_$STAMP/ 2>/dev/null || true
cp -a /etc/usbdevice.d /root/camera_uvc_backup_$STAMP/ 2>/dev/null || true
cp -a /root/camera_uart/camera_aiq_test /root/camera_uvc_backup_$STAMP/ 2>/dev/null || true
```

部署目标：

```text
camera_aiq_test                  -> /root/camera_uart/camera_aiq_test
external/rkscript/usbdevice      -> /usr/bin/usbdevice
zz-camera-uvc-4000x3000.sh       -> /etc/usbdevice.d/zz-camera-uvc-4000x3000.sh
```

设置权限并重建 gadget：

```bash
chmod 0755 /root/camera_uart/camera_aiq_test /usr/bin/usbdevice
chmod 0755 /etc/usbdevice.d/zz-camera-uvc-4000x3000.sh
systemctl restart usbdevice
```

此时 USB 同时暴露 RNDIS 网络和一个 UVC 视频接口。重启服务会使 USB 主机侧
设备短暂断开并重新枚举，`192.168.55.1` 的 SSH 连接也会短暂中断后恢复。

## 6. 板端运行

默认参数已经对应当前链路：

```text
IQ:      /etc/iqfiles/cam0 和 /etc/iqfiles/cam1
sensor:  imx586
video:   /dev/video-camera0 和 /dev/video-camera1
size:    4000x3000
```

启动统一程序：

```bash
cd /root/camera_uart
./camera_aiq_test
```

在程序提示符内执行：

```text
status 0
stream-start 0
capture-status 0
uvc-start 0
uvc-status
```

`uvc-start 0` 必须放在 `stream-start 0` 后。主机尚未打开 UVC 时，
`host_streaming=0` 和 `skipped_no_host` 增长是正常现象。

## 7. PC 端验证

必须把 RK3576 的 **OTG/device 数据口** 连接到要抓图的电脑。`ttyUSB0` 所在的
USB 转串口线只用于调试，不能承载 UVC 视频。重新枚举后在该电脑定位新 UVC 节点：

```bash
lsusb -d 2207:00ff
v4l2-ctl --list-devices
v4l2-ctl -d /dev/videoX --list-formats-ext
```

期望只看到：

```text
MJPG 4000x3000: 10 fps, 5 fps
```

先以 5 fps 保存 30 帧，不转码。当前板端实际枚举为 USB 2.0 high-speed，5 fps
是优先验证档位；链路稳定后再改为 10 fps：

```bash
ffmpeg -f v4l2 -input_format mjpeg -video_size 4000x3000 -framerate 5 \
  -i /dev/videoX -frames:v 30 -c copy /tmp/rk3576_uvc_4000x3000.mjpeg
```

检查文件并解码首帧：

```bash
ffprobe /tmp/rk3576_uvc_4000x3000.mjpeg
ffmpeg -i /tmp/rk3576_uvc_4000x3000.mjpeg -frames:v 1 \
  /tmp/rk3576_uvc_4000x3000.jpg
file /tmp/rk3576_uvc_4000x3000.jpg
```

然后回到板端执行 `uvc-status`。通过标准：

- `negotiated=4000x3000@5fps/MJPG` 或 `10fps/MJPG`；
- `submitted`、`encoded`、`sent` 持续增长；
- `encode_errors=0`、`last_mpp_error=0`；
- PC 端得到 4000x3000 的有效 JPEG/MJPEG；
- 停止命令 `uvc-stop` 后程序正常返回，不残留占用 UVC 节点的进程。

如果当前连接实际只有 USB 2.0，10 fps 可能受图像复杂度和 JPEG 大小影响。
先改用 `-framerate 5` 验证稳定性；USB 3.x 连接是 4000x3000@10 fps 的推荐
条件。

## 8. 停止和回退

正常停止：

```text
uvc-stop
stream-stop 0
quit
```

回退时先停止服务和程序，再从 `/root/camera_uvc_backup_时间戳` 恢复
`/usr/bin/usbdevice`，删除 UVC hook，最后重启 `usbdevice`：

```bash
systemctl stop usbdevice
rm -f /etc/usbdevice.d/zz-camera-uvc-4000x3000.sh
cp -a /root/camera_uvc_backup_时间戳/usbdevice /usr/bin/usbdevice
systemctl start usbdevice
```
