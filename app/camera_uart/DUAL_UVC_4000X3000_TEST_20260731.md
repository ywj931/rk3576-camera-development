# RK3576 + 双 IMX586 UVC 实现、测试与回退记录

## 1. 当前结论

本版本已将两颗 IMX586 分别输出为两个标准 UVC 视频接口：

```text
IMX586 camera0 -> RKISP/RKAIQ -> MPP MJPEG -> UVC uvc.0 -> PC /dev/video0
IMX586 camera1 -> RKISP/RKAIQ -> MPP MJPEG -> UVC uvc.1 -> PC /dev/video2
```

当前电脑枚举结果中 `/dev/video1`、`/dev/video3` 是 UVC 元数据节点，不能用于
取图。USB 重新插拔后编号可能变化，应通过 `v4l2-ctl --list-devices` 重新确认。

两路视频均支持：

```text
MJPG 4000x3000 @ 10 fps
MJPG 4000x3000 @ 5 fps
```

这是双路 UVC 验证用的自由运行版本。两路设备树中的
`sony,xvs-slave-mode` 已暂时移除，避免 IMX586 在没有外部 XVS 脉冲时一直等待、
无法产生帧。该改动不等于完成硬件同步；恢复 XVS 从模式前必须先接通并验证外部
同步脉冲。

## 3. 实现改动

1. 两路 CSI 设备树临时去掉 `sony,xvs-slave-mode`，让两颗 IMX586 自由运行。
2. USB configfs 同时创建 `uvc.0` 和 `uvc.1`，并设置 `UVC_CNT=2`。
3. Rockchip UVC 控制层由单个全局视频实例改为按 UVC 索引管理，camera0 只写
   `uvc.0`，camera1 只写 `uvc.1`。
4. `camera_aiq_test --uvc-daemon` 启动两路 AIQ、两路 V4L2 采集和两路 UVC 输出。
5. 每路使用独立的最新帧队列和独立 MPP MJPEG 编码器，互不串帧。
6. MPP 输入按 16 像素对齐：4000x3000 NV12 的编码高度步长为 3008；逐行复制
   有效图像并填充对齐区。未对齐时会出现 `mpp_jpgenc processing time out` 和
   只有 623 字节的残缺 JPEG。
7. UVC 后端按主机协商的 10 fps 或 5 fps 主动限速，避免传感器约 20 fps 的源帧
   全部挤入 USB2 链路。
8. `camera-uvc.service` 开机自动启动，客户侧不需要先运行 SSH 命令。

## 4. 板端检查

板卡上电并把 Type-C device/OTG 数据口连接电脑后，执行：

```bash
systemctl status camera-uvc.service --no-pager
pgrep -a camera_aiq_test
ls -l /dev/video49 /dev/video50
journalctl -u camera-uvc.service -n 80 --no-pager
```

本次实测状态：

```text
camera-uvc.service: active (running)
camera_aiq_test:    --uvc-daemon
camera0 stream:     STARTED
camera1 stream:     STARTED
UVC gadget nodes:   /dev/video49、/dev/video50
```

板端 `/dev/video49`、`/dev/video50` 是 gadget 输出节点，不要用
`v4l2-ctl --stream-mmap` 从它们采集。

## 5. 电脑端测试流程

### 5.1 确认识别和格式

```bash
lsusb | grep 2207
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video0 --list-formats-ext
v4l2-ctl -d /dev/video2 --list-formats-ext
```

本次实测 USB 设备为 `2207:0005`，两个可采集节点为 `/dev/video0` 和
`/dev/video2`。

### 5.2 分别保存一张原始 MJPEG 图片

```bash
ffmpeg -y -f v4l2 -input_format mjpeg -video_size 4000x3000 \
  -framerate 10 -i /dev/video0 -frames:v 1 -c:v copy cam0.jpg

ffmpeg -y -f v4l2 -input_format mjpeg -video_size 4000x3000 \
  -framerate 10 -i /dev/video2 -frames:v 1 -c:v copy cam1.jpg
```

### 5.3 两路同时连续传输

```bash
v4l2-ctl -d /dev/video0 \
  --set-fmt-video=width=4000,height=3000,pixelformat=MJPG \
  --set-parm=10 --stream-mmap=4 --stream-count=100 --stream-to=/dev/null &
PID0=$!

v4l2-ctl -d /dev/video2 \
  --set-fmt-video=width=4000,height=3000,pixelformat=MJPG \
  --set-parm=10 --stream-mmap=4 --stream-count=100 --stream-to=/dev/null &
PID1=$!

wait "$PID0"
wait "$PID1"
```

验证 5 fps 时只需把两处 `--set-parm=10 --stream-count=100` 改成
`--set-parm=5 --stream-count=50`。

`mpp_jpgenc processing time out`、服务重启或有效 JPEG 无法解码，才属于失败。

## 7. 恢复原 XVS 版本

以下操作会恢复修改前的完整启动分区和应用，执行前先确认备份目录存在：

```bash
test -s /root/camera_uart/backups/20260731_before_dual_uvc/boot_partition_before_dual_uvc.img
systemctl stop camera-uvc.service

install -m 0755 \
  /root/camera_uart/backups/20260731_before_dual_uvc/camera_aiq_test \
  /root/camera_uart/camera_aiq_test
install -m 0755 \
  /root/camera_uart/backups/20260731_before_dual_uvc/usbdevice \
  /usr/bin/usbdevice
install -m 0644 \
  /root/camera_uart/backups/20260731_before_dual_uvc/camera-uvc.service \
  /etc/systemd/system/camera-uvc.service
install -m 0755 \
  /root/camera_uart/backups/20260731_before_dual_uvc/usbdevice.d/uvc-only.sh \
  /etc/usbdevice.d/uvc-only.sh

dd if=/root/camera_uart/backups/20260731_before_dual_uvc/boot_partition_before_dual_uvc.img \
  of=/dev/mmcblk0p3 bs=4M conv=fsync
systemctl daemon-reload
sync
reboot
```

恢复后两颗 IMX586 会重新进入原 XVS 从模式。没有外部同步脉冲时再次出现
`frames=0` 属于预期现象，因此硬件同步版本应在 XVS 信号接好以后再刷回。
