# RK3576 第四、第五阶段全局检查报告

检查日期：2026-07-24

检查目录：`/home/ywj/rk3576_sdk/TaishanPi-3-Linux`

## 1. 总体结论

第四、第五阶段尚未全部完成。

已经成立的主链路是双路 RKAIQ 控制、双路 V4L2 采集、异步 NV12 保存、
camera0 UVC 输出，以及 cam0/cam1 双路 RTSP 的代码和 ARM64 构建链。

尚未成立的主链路是 UART 到相机后端的实际调用、硬件同步开关、Trigger、
PPS、NMEA/GPRMC 与帧号/UTC 绑定。UVC、双路 RTSP 和 eMMC 还各有现场验收项。

## 3. 调用链检查

本地控制链完整：

```text
camera_aiq_test
  -> camera_backend        -> RKAIQ 双路控制
  -> capture_backend       -> V4L2 双路采集与异步保存
  -> camera_uvc_backend    -> camera0 MPP MJPEG -> UVC gadget
  -> camera_net_backend    -> cam0/cam1 MPP H.264 -> RTSP /cam0,/cam1
```

采集输出链完整：

```text
capture_backend DQBUF
  -> capture_to_outputs
     -> camera0 帧提交到 UVC
     -> camera0/camera1 帧分别提交到网络后端
```

UART 控制链在协议解析后中断：

```text
/dev/ttyS9
  -> camera_uartd 帧解析
  -> PING / GET_STATUS
  -X-> camera_backend / capture_backend / UVC / RTSP
```

硬件时间链不存在：

```text
Trigger/PPS GPIO
  -X-> DTS/IRQ
  -X-> IMX586 外触发模式
  -X-> trigger_id 与双路 frame_id
  -X-> NMEA UTC
```

## 4. 本次修复

- UVC 只接收 camera0 帧，不再把 camera1 帧无意义地提交到单路 UVC 后端。
- 修复共享 UVC 控制代码中的空 `if`，避免退出清理被无条件执行。
- 更新 RTSP 文档和命令说明，使其与双路 `/cam0`、`/cam1` 实现一致。
- 为 `camera_uartd` 和 `camera_uart_test` 增加 SDK 主机 ARM64 交叉构建目标。
- UART 协议自测在运行前强制重建当前主机版本，避免误执行 ARM64 文件。

## 6. 已有测试证据边界

- 双路控制报告证明独立曝光、模拟增益和帧率控制成立。
- IQ 的 `CISMinFps` 改为 2 后，cam0 请求 4 fps 实测 4.003 fps；
  cam1 请求 2 fps 实测 2.807 fps。若要求严格 2.000 fps，需要新传感器模式。
- 双路保存记录共 39 帧，camera0 为 20 帧、camera1 为 19 帧；
  双路同时保存仅验证 300 ms，不能替代长时间 eMMC 压力测试。
- camera0 RTSP 已验证 4000x3000 H.264 约 10 fps，长运行记录
  `frames=4227`、`sequence_drops=0`、`encoded=1377`。
- UVC 板端生成了有效 4000x3000 JPEG，但测试电脑未枚举到 UVC
  `/dev/videoX`，所以 PC 端抓流仍未闭环。
