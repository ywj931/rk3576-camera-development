# RK3576 + 双 IMX586 + STM32 XVS 2 Hz 复测记录

测试日期：2026-08-06

> 最终状态：cam1 重新插接后已恢复，STM32 重新开启后的双路 60 帧 2/2 Hz
> 测试通过，详见第 8 节。第 2～7 节保留的是故障出现、隔离和恢复过程，不代表
> 当前最终状态。

## 1. 测试条件

- RK3576 已刷入 IMX586 XVS 从模式 boot 镜像。
- STM32F103 持续输出共享 2 Hz XVS 信号。
- 两路 `xvs_input_thin=0`，即每个外部脉冲请求输出一帧。
- 本次未使用示波器，仅使用传感器帧时间戳和帧计数验证。
- RK3576、USB 供电均完全断开后重新连接，启动日志确认是冷启动。

## 2. 冷启动后的相机识别

cam0 通过：

```text
imx586 4-001a: detected imx586 0586 sensor
/dev/video-camera0 -> /dev/video22
I2C4 0x1a = UU
```

cam1 未通过：

```text
imx586 5-001a: Unexpected sensor id(000000), ret(-5)
/dev/video-camera1 不存在
I2C5 0x1a 无响应
```

该错误发生在驱动读取 IMX586 芯片 ID 的阶段，早于开始采集和等待 XVS 脉冲。因此，当前 cam1 问题不是“没有 XVS 脉冲导致不出帧”，而是 cam1 的供电、复位、时钟、I2C、排线或模组链路尚未正常工作。

## 3. cam0 的 STM32 2 Hz XVS 验证

测试命令：

```sh
v4l2-ctl -d /dev/video0 \
  --set-fmt-video=width=4000,height=3000,pixelformat=RG10 \
  --stream-mmap=4 --stream-count=20 \
  --stream-to=/dev/null --stream-poll --verbose
```

除启动过渡帧外，连续帧间隔为：

```text
500.029, 500.029, 500.027, 500.031, 500.030,
500.004, 500.031, 500.027, 500.033, 500.030,
500.027, 500.009, 500.027, 500.033, 500.028,
500.030, 500.029, 500.029 ms
```

判定：

- 20 帧连续采集完成，sequence 为 0～19，无 sequence 跳号。
- 稳态周期约 500.004～500.033 ms。
- 对应频率约 2.000 Hz。
- STM32 的 2 Hz 信号已到达 cam0，cam0 的 XVS 从模式有效。

## 4. 当前结论

| 项目 | 结果 |
|---|---|
| STM32 共享 2 Hz XVS 信号 | 通过（由 cam0 帧周期证明） |
| cam0 XVS 从模式 2 Hz | 通过 |
| cam0 连续帧计数 | 通过，20 帧无跳号 |
| cam1 芯片识别 | 不通过，ID=000000 |
| 双路 2/2 Hz 同步 | 未执行，受 cam1 识别故障阻塞 |
| 两路曝光起点相位差 | 未测试，需要示波器或逻辑分析仪 |
| 4/4、4/2、2/4、2/2 组合 | 未完整测试；STM32 需先改为共享 4 Hz |

## 5. 下一步隔离顺序

1. 临时断开 STM32 到 RK3576 的 FSYNC_CAM 信号线，只保留正常相机连接。
2. RK3576 完全断电至少 10 秒，再重新上电。
3. 检查 cam1 是否出现 `detected imx586 0586 sensor` 以及 `/dev/video-camera1`。
4. 若 cam1 恢复，说明要复查 STM32 信号线实际接点、共地和电平；重新正确接入后再做双路同步。
5. 若 cam1 仍失败，交换 cam0/cam1 模组或排线，判断故障跟随模组/排线，还是固定在 CSI1/I2C5 接口。
6. 只有两颗 IMX586 都能读取到 `0586` 后，才开始双路同步验收。

### 2026-08-06 无 STM32 冷启动复查

已完全断开 STM32，并再次冷启动 RK3576，cam1 仍然报告：

```text
imx586 5-001a: Unexpected sensor id(000000), ret(-5)
```

因此已排除 STM32、FSYNC_CAM 和 XVS 输入电平导致 cam1 无法识别。

进一步检查：

- I2C4 和 I2C5 的 pinctrl 均处于正确的 `i2c4m3-xfer`、`i2c5m3-xfer` 复用状态。
- I2C4 读探测可看到 `0x1a` 和 `0x50`。
- I2C5 读探测看不到任何从设备。
- 对 I2C5 `0x50` 执行读取或组合读取均失败。
- 重新绑定 `imx586` 驱动后，cam1 仍返回 `ID=000000`。
- 驱动没有报告 MCLK 或 regulator 使能失败；软件声明的 cam1 电压分别为 2.8 V、1.8 V、1.2 V，但这不能替代连接器处的万用表实测。

更新判定：cam1 故障与应用、IQ、V4L2 采集和 XVS 无关。故障范围集中在 cam1 模组、排线、连接器、接口侧供电/复位/MCLK，或 I2C5 到模组的物理链路。

## 6. 双路恢复后的验收标准

- 两路同时连续采集至少 60 帧（2 Hz 下约 30 秒）。
- 两路稳态帧间隔均约 500 ms。
- 两路 sequence 不跳号，帧数差不随时间持续增长。
- 逐帧比较两路 V4L2 单调时间戳差，并保存原始日志。
- 软件时间戳只能验证两路稳定跟随同一触发源；最终硬件相位差仍以示波器同时测量 FSYNC_CAM 和两路帧/曝光信号为准。

## 7. cam1 重新插接恢复后的双路复测

重新插接相机硬件并冷启动后，两颗传感器均恢复识别：

```text
imx586 4-001a: detected imx586 0586 sensor
imx586 5-001a: detected imx586 0586 sensor
/dev/video-camera0 -> /dev/video22
/dev/video-camera1 -> /dev/video31
```

这证明之前 cam1 的 `ID=000000` 是相机模组、排线或连接器接触问题，不是
IMX586 驱动、IQ、V4L2 或 XVS 从模式导致。

两路 RAW 节点分别为 cam0 `/dev/video0`、cam1 `/dev/video11`。停止
`camera-uvc.service` 后，同时请求两路各采集 60 帧。两路均成功执行
`VIDIOC_STREAMON`，驱动也都确认进入 XVS 从模式：

```text
imx586 4-001a: XVS slave mode enabled: low-active, input-thin=1/1
imx586 5-001a: XVS slave mode enabled: low-active, input-thin=1/1
```

但本轮每路都只收到 sequence 0，随后 `select timeout`：

```text
cam0 seq=0 ts=244.073165
cam1 seq=0 ts=244.077507
```

第 0 帧的 V4L2 EOF 时间戳相差约 4.342 ms，但没有后续帧，不能据此判定双路
同步精度。`/dev/ttyS9` 配置为 115200、8N1 后，3 秒被动接收为 0 字节；发送
`$XVS,1,PING*2D89\r\n` 后仍收到 0 字节。

当前判定：

- 两颗 IMX586、两路 I2C/MIPI 和 XVS 从模式配置正常。
- 当前没有连续 2 Hz XVS 到达两颗 sensor；双路同时停止排除了 cam1 单路故障。
- STM32 UART 也未响应，但如果当前 STM32 固件只固定输出 PWM、不实现本文协议，
  UART 无响应不能单独证明 MCU 未运行；RAW 无连续帧则直接证明 FSYNC_CAM 当前没有
  有效连续触发。
- 需要复查 STM32 定时器输出到 CN4 pin 23 `FSYNC_CAM`、双方 GND、输出极性和
  电平。XVS 应为空闲高、低脉冲有效、2 Hz 周期约 500 ms。
- 接线恢复后先重复两路 60 帧测试；只有两路各得到 60 帧、周期约 500 ms 且
  sequence 连续，才能判定软件侧 2/2 Hz 跟随通过。

## 8. STM32 重新开启后的最终 2/2 Hz 复测

STM32 重新开启后，再次同时采集 cam0 `/dev/video0` 和 cam1 `/dev/video11`，
每路请求 60 帧。10 秒检查点两路均已获得 20 帧，证明共享 XVS 已恢复连续输出；
最终两路均获得完整 60 帧并以退出码 0 结束，没有 `select timeout`。

统计结果：

| 项目 | cam0 | cam1 |
|---|---:|---:|
| 帧数 | 60 | 60 |
| sequence | 0～59 | 0～59 |
| sequence 跳号 | 0 | 0 |
| 稳态最小周期 | 500.005 ms | 500.003 ms |
| 稳态最大周期 | 500.039 ms | 500.044 ms |
| 稳态平均周期 | 500.026 ms | 500.026 ms |
| 实测帧率 | 1.999897 Hz | 1.999898 Hz |

按相同 sequence 配对 60 帧，V4L2 EOF 单调时间戳统计如下：

```text
sequence mismatch = 0
abs(cam1 EOF - cam0 EOF) min = 2 us
abs(cam1 EOF - cam0 EOF) max = 19 us
abs(cam1 EOF - cam0 EOF) avg = 4.783 us
```

本轮启动采集时内核出现一次：

```text
MIPI_CSI2 ERR2:0xf0000
```

该告警出现在 stream-on/XVS 启动过渡阶段，之后未持续出现，两路 60 帧均完整且
sequence 无跳号。因此本轮功能和软件侧帧计数判定为通过，但该启动瞬态告警应在
后续 1000 帧及反复启停压力测试中继续观察。

最终判定：

- STM32 共享 2 Hz XVS 已同时到达两颗 IMX586：通过。
- 两路 XVS 从模式 2/2 Hz 连续跟随：通过。
- 60 帧 sequence 连续性和两路帧数一致性：通过。
- V4L2 EOF 时间戳配对：通过，软件观察差值 2～19 us。
- 真实曝光起点硬件相位差：尚未验收，仍需示波器同时测量共享 XVS 和两颗
  IMX586 XVS/曝光相关测试点。
- 4/4、4/2、2/4、2/2 四种独立组合：本次 STM32 只输出共享 2 Hz，尚不能验收；
  正式测试需把共享 XVS 改为连续 4 Hz，再用每颗 sensor 的 input-thin 独立选择
  4 Hz 或 2 Hz。
